# 从项目菜单打开 IDE 设计

## 目标

从项目侧栏的右键菜单选择已安装的 Codex 桌面客户端、VS Code 或 Cursor，并直接打开项目根目录。

## 界面

- 在项目右键菜单顶部添加“在 IDE 中打开”及子菜单箭头；编辑和删除仍在下方。
- 子菜单只显示当前 Windows 用户已安装且可启动的 Codex、VS Code、Cursor。
- 没检测到任何支持的编辑器时，显示“未检测到 IDE”，提供重新扫描操作。
- 右键菜单打开时扫描；如需更新，可在 IDE 子菜单中手动重新扫描。
- 点击应用后立即打开目录并关闭菜单。启动失败时，通过应用现有提示条展示可读错误。

## 启动和检测

- Codex 桌面端：检测 Windows 开始菜单中的 Codex AppID，使用注册的 `codex://threads/new?path=...` 协议打开项目工作区。
- VS Code：先从 PATH 中的 `code` 启动器定位其 `Code.exe`，再检查常见用户/系统安装目录；直接以项目路径作为独立参数启动。
- Cursor：先从 PATH 中的 `cursor` 启动器向上定位 `Cursor.exe`，再检查常见用户/系统安装目录；以项目路径和 `--classic` 参数打开编辑器窗口。
- 每次打开时由 Rust 根据项目 ID 从配置中解析目录；只接受固定的编辑器 ID，不接受前端传入任意可执行文件或命令字符串。
- 通过操作系统启动协议或直接启动已解析的 GUI 可执行文件，不经过命令解释器。安装检测结果只保存在当前界面内，不写入项目配置。

## 错误和边界

- 非 Windows 构建返回不支持提示，不提供伪造的安装状态。
- 编辑器扫描失败显示重新扫描；已检测但启动失败显示操作系统返回的错误。
- 项目路径无效时拒绝启动并提示用户先检查项目配置。
- V1 不增加默认编辑器、记忆选择、JetBrains 支持或自定义程序路径设置。

## 验收

- 当前环境中 Codex、VS Code、Cursor 均出现在项目右键菜单的 IDE 子菜单。
- 各编辑器打开时指向正确项目根目录；Cursor 使用 IDE 编辑器窗口。
- 未安装应用不会显示为可选项；重新扫描能刷新列表。
- 项目编辑、删除仍可从同一右键菜单触发。
- 启动器路径含空格或项目路径含空格/中文时也能安全启动；不通过 shell 拼接命令。
